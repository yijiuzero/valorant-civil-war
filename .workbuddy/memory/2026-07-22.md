## 两个用户反馈 bug 修复（V4.2.0 → V4.2.1，纯 bug 修复 +0.0.1）
用户报告：①内战分队——其他人进房间后房主看不到了，且无法进行分队；②内鬼 Lobby——房主不小心退出后重新进提示"该名字已在房间中"。

**根因①**：teamsplit.js `createRoom()` 房主经 `autoJoinLobby()` 插入自己后，仅靠 Realtime 的 INSERT 事件把房主行加进 `currentPlayers`；但房主自己的 INSERT 与刚建立的订阅存在竞态，事件常被漏收 → `currentPlayers` 为空 → 房主不在列表中（"看不到"）且人数<2 → 分队按钮 disabled（"无法分队"）。加入者不踩坑是因为 `joinRoom()` 调了 `refreshPlayers()`。
**修复①**：`createRoom()` 在 `await autoJoinLobby()` 后追加 `await refreshPlayers()`，以 DB 为准加载列表。node --check 通过。

**根因②**：spy-mode.js `joinSpyLobby()` 只要 `state.players` 里同名就硬拦（"该名字已在房间中"），且 `leaveLobbyRoom()` 房主离开即把 phase 置 `closed`；房主误退出（关标签页/误点离开）后房间仍含自己，重进被拦，且无重连路径。
**修复②**：
- `joinSpyLobby()` 取 `me = players.find(name)`，区分"同一用户重连"（me.user_id === 当前 uid → 直接重连，不重复插入、不拦截）与"真正重名"（不同 uid → 拦截）。新玩家仍按 phase 校验。
- `leaveLobbyRoom()` 大厅阶段房主离开仅移除自己、保持房间 lobby 开放以便重连；游戏阶段或大厅无人离开才置 closed。
- `renderLobbyGameView()` 新增 `closed`/`done` 友好提示（房主已离开），避免渲染异常 markup。

**版本/缓存**：index.html 两处 V4.2.0→V4.2.1；?v = teamsplit 11→12、spy-mode 12→13（auth/css/app/app-data 未改不动）。PROJECT_CONTEXT.md 标题+历史行同步（本地 gitignore）。
